# Backend — Цифровой механик

Backend — отдельное приложение на **Python + FastAPI**. Оно связывает frontend, приватные Mock API организаторов и будущий RAG/AI-агент.

## Важно про репозитории

Код Mock ML и Mock ТОиР, `vehicles.json`, `fault_types.json`, PDF-руководства и RAG-индексы **не входят в этот репозиторий**. Организаторские Mock API запускаются из отдельного приватного репозитория. Backend подключается к ним только по URL из `.env`.

Для локального списка машин backend читает `vehicles.json` по внешнему пути `VEHICLE_CATALOG_PATH`. Файл не копируется в backend. В Docker/на сервере его можно подключить как read-only volume либо заменить реализацию каталога на отдельный API-адаптер, если такой endpoint будет доступен.

## Запуск на Windows (PowerShell)

Из папки `backend`:

```powershell
py -3.11 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
Copy-Item .env.example .env
uvicorn app.main:app --reload --port 8000
```

Документация API: <http://127.0.0.1:8000/docs>
Проверка: <http://127.0.0.1:8000/health>

Если PowerShell блокирует активацию окружения, можно использовать `cmd` или временно разрешить скрипты для текущего окна PowerShell.

## Переменные окружения

- `MOCK_ML_BASE_URL` — адрес приватного Mock ML (по умолчанию `http://127.0.0.1:8001`).
- `MOCK_TOIR_BASE_URL` — адрес приватного Mock ТОиР (по умолчанию `http://127.0.0.1:8002`).
- `VEHICLE_CATALOG_PATH` — абсолютный или относительный путь к `vehicles.json` в приватной папке.
- `KNOWLEDGE_BASE_PATH` — внешняя папка с разрешёнными PDF и индексом RAG.
- `RAG_ENABLED` — флаг будущей реализации RAG; сейчас ответы не генерируются по документам.
- `CORS_ORIGINS` — адрес frontend.

Относительные пути разрешаются относительно рабочей директории процесса. Для надёжности лучше указать абсолютные пути в локальном `.env`.

## API backend

Все прикладные маршруты находятся под `/api/v1`:

| Метод | Маршрут | Назначение |
|---|---|---|
| GET | `/vehicles` | список ТС и история проверок из внешнего каталога |
| GET | `/vehicles/{vehicle_id}` | карточка ТС |
| POST | `/diagnostics` | проксирует запрос в Mock ML `/diagnose` |
| POST | `/assistant/chat` | точка входа диалога с агентом |
| POST | `/tickets` | проверяет заявку и передаёт её в Mock ТОиР |

## Архитектура

- `api/` — HTTP-маршруты.
- `schemas/` — входные и выходные модели API.
- `services/` — прикладная логика.
- `integrations/` — клиенты внешних сервисов Mock ML и Mock ТОиР.
- `repositories/` — чтение каталога машин из внешнего файла.
- `domain/` — правила предметной области.

RAG и агент пока представлены отдельными точками расширения. До подключения настоящих руководств backend не должен выдавать технические нормативы или фиктивные ссылки. Отсутствие источников означает честный отказ от ответа по документации.

## Ограничения текущего каркаса

- Mock ML принимает только `vehicle_id` и `session_id`, аудио в backend не загружается.
- История заявок пока не хранится в базе данных. Mock ТОиР возвращает только `ticket_id`.
- `POST /tickets` повторно запрашивает результат ML-диагностики на backend по `vehicle_id` и `session_id`. Поэтому backend не доверяет диагнозу, который мог бы подменить браузер, и проверяет совпадение `anomaly_type` перед отправкой заявки в ТОиР.
- Для полноценного агента нужно добавить LLM-провайдера и tool-calling: диагностика, RAG-поиск и создание заявки должны быть отдельными инструментами.
