# Backend — Цифровой механик

Backend — отдельное приложение на **Python + FastAPI**. Оно связывает frontend, приватные Mock API организаторов и будущий RAG/AI-агент.

## Важно про репозитории

Код Mock ML и Mock ТОиР, `vehicles.json`, `fault_types.json`, PDF-руководства и RAG-индексы **не входят в этот репозиторий**. Организаторские Mock API запускаются из отдельного приватного репозитория. Backend подключается к ним только по URL из `.env`.

Для локального списка машин backend читает `vehicles.json` по внешнему пути `VEHICLE_CATALOG_PATH`. Файл не копируется в backend. В Docker/на сервере его можно подключить как read-only volume либо заменить реализацию каталога на отдельный API-адаптер, если такой endpoint будет доступен.

## Запуск на Windows (PowerShell)

Из папки `backend`:

```powershell
py -3.11 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
Copy-Item .env.example .env
uvicorn app.main:app --reload --port 8000
```

Документация API: <http://127.0.0.1:8000/docs>
Проверка: <http://127.0.0.1:8000/health>

Если PowerShell блокирует активацию окружения, можно использовать `cmd` или временно разрешить скрипты для текущего окна PowerShell.

## Индекс руководств (RAG)

Положите шесть PDF Заказчика в папку `KNOWLEDGE_BASE_PATH` под исходными именами (список в `app/rag/manuals.py`) и постройте индекс:

```powershell
python -m app.rag.indexer
```

Индекс (`KNOWLEDGE_BASE_PATH/index/chunks.jsonl`, ~15 с) содержит текст руководств, поэтому лежит рядом с PDF, вне Git. Страницы — по нумерации PDF. Оглавления в индекс не попадают: оглавление не является доказательством. Страницы без текстового слоя распознаются через `tesseract` с языком `rus`, если он установлен (`TESSDATA_DIR` — папка с `rus.traineddata`, если её нет в системе). Это 7 страниц-сканов в 236.01.01 РК (регулировка клапанов и ТНВД). Фрагменты из OCR помечены `ocr: true`: числа из распознанных таблиц надо сверять с изображением страницы. Без tesseract эти страницы просто пропускаются, остальное работает.

Проверка поиска (только руководства на указанный двигатель):

```powershell
python -m app.rag.search "ЯМЗ-236М2" "момент затяжки болтов крышек коренных подшипников"
```

## Переменные окружения

- `MOCK_ML_BASE_URL` — адрес приватного Mock ML (по умолчанию `http://127.0.0.1:8001`).
- `MOCK_TOIR_BASE_URL` — адрес приватного Mock ТОиР (по умолчанию `http://127.0.0.1:8002`).
- `VEHICLE_CATALOG_PATH` — абсолютный или относительный путь к `vehicles.json` в приватной папке.
- `KNOWLEDGE_BASE_PATH` — внешняя папка с разрешёнными PDF и индексом RAG.
- `CORS_ORIGINS` — адрес frontend.

Относительные пути разрешаются относительно рабочей директории процесса. Для надёжности лучше указать абсолютные пути в локальном `.env`.

## API backend

Все прикладные маршруты находятся под `/api/v1`:

| Метод | Маршрут | Назначение |
|---|---|---|
| GET | `/vehicles` | список ТС и история проверок из внешнего каталога |
| GET | `/vehicles/{vehicle_id}` | карточка ТС |
| POST | `/diagnostics` | проксирует запрос в Mock ML `/diagnose` |
| POST | `/assistant/chat` | точка входа диалога с агентом |
| POST | `/tickets` | проверяет заявку и передаёт её в Mock ТОиР |

## Архитектура

- `api/` — HTTP-маршруты.
- `schemas/` — входные и выходные модели API.
- `services/` — прикладная логика.
- `integrations/` — клиенты внешних сервисов Mock ML и Mock ТОиР.
- `repositories/` — чтение каталога машин из внешнего файла.
- `domain/` — правила предметной области.

- `agent/` — инструменты агента (`tools.py`) и проверка ответа по источникам (`checks.py`).
- `rag/` — реестр руководств, индексатор, поиск.

## Агент

`POST /api/v1/assistant/chat` — `{vehicle_id, message, conversation_id?, session_id?, confirm_warning?}`. LLM (OpenAI-совместимый API, по умолчанию DeepSeek через OpenRouter, `LLM_*` в `.env`) сама выбирает инструменты:

| Инструмент | Что делает |
|---|---|
| `get_diagnosis` | результат проверки из Mock ML + вычисленный приоритет и причина блокировки заявки |
| `search_manual` | поиск только по руководствам на двигатель этой машины, фрагменты с ключом `руководство:страница` |
| `create_ticket` | заявка в Mock ТОиР |

Правила, которые выполняются в коде независимо от LLM (`domain/diagnostic_rules.py`, `agent/`):

- `check_failed` / `bad` — заявки нет; `confidence < 0.50` — повторная проверка, заявки нет; `warning` — заявка только с `confirm_warning=true` (кнопка в UI).
- Код неисправности, невозможный для топлива машины (F12/F13 у дизеля, F08 у бензина), — заявки нет: в руководстве нет инструкции по такому узлу.
- Ссылки заявки — только на найденные фрагменты, с дословной цитатой; числа в работах — только из процитированных фрагментов.
- Приоритет: базовая критичность F-кода ± один уровень по `anomaly_score` (≥ 0,85 вверх, < 0,60 вниз). Если руководство прямо запрещает эксплуатацию (подтверждённая цитата) — `high`.
- Каждое число в ответе должно быть в процитированном фрагменте или в данных проверки; иначе один повтор модели, затем явное предупреждение в ответе.

Ответ содержит `steps` (каждый вызов модели с назначением: `llm:search_manual`, `llm:create_ticket`, `llm:answer`, `llm:fix`; токены, стоимость, время) и `cost_usd`.

## Калькулятор стоимости

```powershell
python -m app.cost_report --out ../docs/cost.md
```

Прогоняет реальные сценарии через агента (по машине с отклонением на каждое руководство, норма, сбой записи), берёт фактически списанную OpenRouter стоимость и пишет [docs/cost.md](../docs/cost.md): стоимость сценария, разбивка по шагам, разовая индексация, пересчёт на парк с явными допущениями. Нужны запущенные заглушки и индекс; прогон стоит около $0.1.

## Ограничения текущего каркаса

- Mock ML принимает только `vehicle_id` и `session_id`, аудио в backend не загружается.
- История заявок пока не хранится в базе данных. Mock ТОиР возвращает только `ticket_id`.
- `POST /tickets` повторно запрашивает результат ML-диагностики на backend по `vehicle_id` и `session_id`. Поэтому backend не доверяет диагнозу, который мог бы подменить браузер, и проверяет совпадение `anomaly_type` перед отправкой заявки в ТОиР.
- Диалоги и созданные заявки хранятся в памяти процесса (один worker), после перезапуска теряются.
