# Цифровой механик — Frontend

Веб-интерфейс для проекта «Цифровой механик» на хакатоне «ИИкузница».

## Что внутри

- **Рабочее место механика** (`/`) — выбор автомобиля, результат проверки двигателя и чат-помощник.
- **Автопарк** (`/fleet`) — сводная информация по автомобилям и результатам проверок.
- **Заявки** (`/tickets`) — форма создания заявки на дефектовку.

## Технологии

React, TypeScript, Vite, React Router, Recharts, Lucide React и i18next.

## Запуск на Windows

Нужен установленный Node.js версии 20.19+ или 22.12+.

1. Откройте PowerShell в папке проекта.
2. Установите зависимости:

   ```powershell
   npm install
   ```

3. Создайте файл локальных настроек:

   ```powershell
   Copy-Item .env.example .env
   ```

4. Запустите frontend:

   ```powershell
   npm run dev
   ```

5. Откройте адрес, который появится в терминале. Обычно это `http://localhost:5173`.

Остановить сервер можно сочетанием `Ctrl + C`.

## Полезные команды

```powershell
npm run dev      # запуск для разработки
npm run build    # проверка TypeScript и production-сборка
npm run preview  # просмотр production-сборки
npm run lint     # проверка TypeScript
```

## Режимы работы

По умолчанию в `.env` включён локальный демонстрационный режим:

```env
VITE_USE_MOCKS=true
```

В этом режиме frontend использует тестовые данные, которые находятся в `src/data/mock.ts`. Они нужны для разработки интерфейса и не являются результатами реальной диагностики.

Чтобы обращаться к backend, укажите:

```env
VITE_USE_MOCKS=false
VITE_ML_API_URL=http://localhost:8001
VITE_AGENT_API_URL=http://localhost:8002
VITE_TOR_API_URL=http://localhost:8003
```

После изменения `.env` перезапустите `npm run dev`.

### Подключение мок-сервисов хакатона

В архиве организаторов находятся два отдельных сервиса:

- Mock ML — `http://localhost:8001`, метод `POST /diagnose`.
- Mock ТОиР — `http://localhost:8002`, метод `POST /tickets`.

Для обращения к ним адрес ТОиР в `.env` должен быть `VITE_TOR_API_URL=http://localhost:8002`. Сервис помощника (Agent API) в архив мок-сервисов не входит — его адрес и формат ответа нужно согласовать с backend-командой. Сам frontend пока ожидает от него метод `POST /chat`.

Список автомобилей и история проверок для мок-сценариев организаторов находятся в `data/vehicles.json` внутри их архива. Mock ML не отдаёт список автомобилей и не принимает аудиофайлы: для диагностики ему передаются `vehicle_id` и `session_id`.

## Структура проекта

```text
src/
  app/                 маршруты и настройка приложения
  components/
    layout/            общая оболочка и навигация
    ui/                повторно используемые элементы интерфейса
  data/                локальные демонстрационные данные
  features/
    diagnostics/       рабочее место механика
    tickets/           создание заявки на дефектовку
    fleet/             экран автопарка
  i18n/                языковые настройки
  lib/api/             запросы к backend-сервисам
  styles/              общие стили
  types/               типы TypeScript
```

## Важно

- Frontend не анализирует звук двигателя самостоятельно. Акустическую диагностику выполняет отдельный сервис.
- При результате `check_failed` нельзя показывать предположительный диагноз.
- Ремонтные рекомендации должны сопровождаться ссылками на источник и страницу руководства. Не выдавайте демонстрационные тексты за реальные инструкции.
- Не добавляйте в Git заводские PDF-руководства, извлечённый из них текст и RAG-индексы.
