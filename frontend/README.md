# Цифровой механик — Frontend

React + TypeScript + Vite, Recharts, Lucide, i18next. Все данные и ответы приходят из backend (`/api/v1`), моков во фронтенде нет.

## Запуск

Нужен Node.js 20.19+ или 22.12+ и запущенный backend на `http://127.0.0.1:8000` (см. `backend/README.md`).

```powershell
npm install
npm run dev
```

Открыть http://localhost:5173. Vite проксирует `/api` на backend (`vite.config.ts`), поэтому с телефона в той же сети страница открывается по `http://<IP компьютера>:5173` без настройки CORS. Другой адрес backend — `VITE_API_URL` в `.env` (см. `.env.example`).

## Страницы

- `/` — рабочее место механика. Выбор ТС и проверки, «Получить результат диагностики»: карточка вердикта приходит сразу из `/diagnostics` (статус, тип, уверенность, приоритет, причина, по которой заявка не создаётся), затем агент объясняет результат со ссылками на страницы руководства. Кнопка заявки отправляет агенту команду; при записи с помехами — отдельная кнопка «Подтверждаю, создать заявку» (`confirm_warning`). Ниже — график anomaly_score по истории проверок (B2). `/?vehicle=<госномер>` открывает нужное ТС.
- `/fleet` — режим главного механика (B3): сводка норма / внимание / карантин по последней проверке, фильтр по клику на карточку, приоритетный список, история проверок машины, переход в рабочее место.
- `/tickets` — заявки, созданные агентом с момента запуска backend.

Правила (пороги, приоритет, допустимость заявки) считает backend; фронтенд их только показывает.

## Структура

```text
src/
  app/            маршруты
  components/     оболочка, ErrorBoundary, UI: Markdown (ответ агента), ScoreChart, бейджи
  features/       diagnostics (механик), fleet (главный механик), tickets
  lib/api.ts      клиент backend и подписи
  types/domain.ts контракты API
```
